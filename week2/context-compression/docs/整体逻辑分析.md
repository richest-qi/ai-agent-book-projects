## 1) 策略是怎么“切换并生效”的？

核心链路是：

- `main.py` 里让你选 1~6，映射到 `CompressionStrategy` 枚举
- 创建 `ResearchAgent(..., compression_strategy=strategy, ...)`
- agent 在执行 `search_web` 后，会把结果交给 `ContextCompressor.compress_search_results(...)`
- `compress_search_results` 根据当前策略分发到对应实现函数

对应代码就是这个分发入口：

```94:108:week2/context-compression/compression_strategies.py
if self.strategy == CompressionStrategy.NO_COMPRESSION:
    return self._no_compression(search_results)
elif self.strategy == CompressionStrategy.NON_CONTEXT_AWARE_INDIVIDUAL:
    return self._non_context_aware_individual_summary(search_results)
elif self.strategy == CompressionStrategy.NON_CONTEXT_AWARE_COMBINED:
    return self._non_context_aware_combined_summary(search_results)
elif self.strategy == CompressionStrategy.CONTEXT_AWARE:
    return self._context_aware_summary(search_results, query, current_context)
elif self.strategy == CompressionStrategy.CONTEXT_AWARE_CITATIONS:
    return self._context_aware_with_citations(search_results, query, current_context)
elif self.strategy == CompressionStrategy.WINDOWED_CONTEXT:
    return self._no_compression(search_results)
```

### 各策略机制（按你的 1~6）

- `1 NO_COMPRESSION`：工具返回什么就塞什么（几万到十几万字符很常见）
- `2 Individual`：每个网页先单独摘要，再拼接
- `3 Combined`：先拼所有网页，再做一次总摘要
- `4 Context-aware`：摘要时带上 query + 当前上下文，做“问题导向”压缩
- `5 Context-aware + citations`：同 4，但要求输出 `[1][2]` 引用并附 Sources
- `6 Windowed`：前期不压缩；当 prompt token 超过上下文窗口 80% 才批量压缩历史 tool 消息

你选 1 时，agent 在写消息历史时会走“原始内容”分支，所以 token 飙升很快：

## 2) 工具调用你理解得对吗？

是的，你理解得很准。

### 工具是怎么定义给模型的

agent 通过 OpenAI-compatible 的 `tools=function` 暴露两个函数：

- `search_web(query, num_results)`
- `fetch_webpage(url)`

模型在回复里触发 tool call，agent 解析后执行本地 Python 函数。

### `search_web` 实际是什么

`search_web` 调的是：

- `POST https://google.serper.dev/search`（通过 `Config.SERPER_BASE_URL`）
- Header 用 `X-API-KEY: SERPER_API_KEY`

所以它是 **Serper API**，底层来源是 Google 搜索结果，但不是你直接调 Google 官方 Search API。

### `fetch_webpage` 做什么

- 对每条搜索结果 URL 再 `requests.get`
- `BeautifulSoup` 去脚本/样式/导航等
- `html2text` 转文本
- 超长截断（`MAX_WEBPAGE_LENGTH`）
- 做缓存，避免重复抓取

你日志里出现的 `403`（Forbes）和 `429`（YouTube）也很正常，说明抓取端确实是直接访问网页，受目标站点反爬/限流影响。
