### 1.稀疏（sparse）
每个文档可以看成「很多词 → 每个词一个权重」。绝大多数词在这个文档里**根本没出现**，权重就是0；只有少数词有非零权重。这种「一大堆0、寥寥几个非零」的表示就叫**稀疏**。和「稠密向量」（每个维度都有值，比如深度学习embedding）是两种风格。   
### 2.倒排索引（inverted index）
正向是：文档 →  里面有哪些词   
倒过来是：词 → 出现在哪些文档里    
#### 一个小例子  
假设库里有**4篇文档**（编号0、1、2、3）,内容极简：    
| 文档 ID | 内容（已切成词） |
|--------|-------------------|
| 0 | 猫、喜欢、鱼 |
| 1 | 狗、喜欢、球 |
| 2 | 机器、学习、算法 |
| 3 | 机器、学习、框架 |  

**正向存储**（文档 → 词）  
要知道「哪些文档包含『学习』」，你得从文档0看到文档3，一篇篇检查——**每搜一次都要扫全文**，文档多了就很慢。   
**倒排索引**（词 → 文档列表）   
- 「学习」→ [2, 3]
- 「机器」→ [2, 3]
- 「喜欢」→ [0, 1]
- 「猫」→ [0]
- ……      

**搜"机器学习"时为什么不扫遍每篇文档？**   
"机器学习"会先被切成两个查询词：**机器**、**学习**。   
1. **查表**（像查字典）：  
- 「机器」→ 文档 [2, 3]  
- 「学习」→ 文档 [2, 3]  
2. **合并（求候选）**     
通过查表知道，文档2和3，就是「至少同时包含」"机器"、"学习"这两个词的候选。   
你**从头到尾只读了两个小列表**，没有打开0、1的正文。    
3. **打分**   
只对2、3这两篇文章算BM25；文档0、1跟这两个词无关，**根本不用算**。       

如果用「暴力法」：要对4篇都读一遍、数词、算分。   
用倒排：**先缩小到少量候选**，再算分，文档成千上万时差距巨大。     

小结：**不是「不读文档」，而是先用「词 → 文档ID列表」把可能相关的文档缩成一小撮，再对这一小撮算分；大部分文档永远进不了候选名单。**
### 3.BM25
BM25(Best Matching 25)，一种**给文档打分**的公式：查询里的每个词，若在某文档里出现得多、且这个词在整个库里比较稀有（不是到处都有），文档得分就更高；同时会**惩罚特别长的文档**（避免长文靠重复词霸榜）。参数`k1`、`b`控制「词频多敏感」和「长度惩罚多强」。
#### 词频TF：不是「越多越好到没边」
同样搜"学习"：
- A文里"学习"出现1次
- B文里"学习"出现5次  
一般会认为B更相关一点，但**不能无限涨**：出现100次不比出现10次「好十倍」。BM25用词频函数做了一个饱和：次数多了，加分越来越不明显。   
**参数k1**就是在调：**次数多了以后，饱和得快还是慢**（k1大 → 更看重「多出现几次」）。  

##### 举个例子  
10个同学各交一篇**一句话**小报（总库N=10）。老师搜：**「足球 周末」**。
- 小报1：「我**周末**踢**足球**。」（各 1 次）
- 小报2:「**周末周末周末**都去踢**足球足球足球足球**。」（堆砌重复）   

若光看次数，2会碾压1。但人读起来，2并没有「更懂足球周末」四倍那么多。  
BM25对词频用**带饱和度的曲线**：多出现会加分、但**加到一定程度就涨慢了**。   
这就是k1调的：**「多得厉害时，还要多给多少分才算合理」。**

#### IDF：在整个库里比较稀有  
- 「的、是、学习」里，「的」几乎每篇都有 → 区分度低，重要性低。
- 「机器学习」里的「机器」在某领域文档里只在少数篇出现 → 稀有，更能说明「这篇就是在讲这个主题」。  

BM25会给稀有词**更高的权重**。    
##### 举个例子  
10个同学各交一篇**一句话**小报（总库N=10）。老师搜：**「足球 周末」**。
- 「的、我、去」几乎每个小报都有 → **不稀奇**，对区分「谁最贴查询」帮助小。
- 「门将」全班只有两篇提到 → **很显眼**，一旦出现，更像「真的要讲足球」的信号。     

BM25给**少见的词更高的“话语权”**：不仅仅考虑出现次数这一项，还要乘上「在全库有多稀有」。   
IDF想表达的就是：**烂大街的词权重要降一点**。
#### 长度归一化：惩罚特别长的文档   
很长的一篇文章，同一个词很容易**重复出现很多次**，词频绝对次数会偏大。  
若不做处理，长文可能只靠「词出现次数多」就排在短文前面。  
BM24会用**文档长度**做矫正：**同样条件下，偏长的文档不会因为「更长」就自动占便宜**。  
**参数b**就是在调：**长度惩罚有多狠**（b 越大 → 越长越吃亏一点；b=0 表示不怎么惩罚长度）。
##### 举个例子
10个同学各交一篇**一句话**小报（总库N=10）。老师搜：**「足球 周末」**。   
假设有人交了**一整页**，里面里面「周末」出现了很多次，只因为**文章特别长**。   
短文里「周末」只出现两次，但更「句句都在点上」。  
BM25会按**这篇有多长（相对平均长度）**做一点校正：**别光靠「长 + 重复多」就把分数抬上天。**   
**b**就是：**你觉得「长短不公平严重」时，就多校正一点（b大）；觉得长度无所谓，就少校正（b小）**。   

#### 总结  
对每个查询词，BM25都在问三件事：  
- **在这篇里这个词算不算"说得够多但别吹过头"（tf+k1）？**
- **这个词在全库中是不是很"扎眼"（稀有则权重大）?**
- **这篇是不是特别长，要把"靠长度堆出来的次数"往下拉一拉（长度+b）？**





1.**建索引**：把一段段文字送进去，系统会**分词***（把句子拆成词，处理数字、驼峰名等），更新倒排索引。   
2.**搜索**：你输入查询，系统同样分词，用倒排索引找到**可能相关文档**，再用BM25**算分**、**排序**。
