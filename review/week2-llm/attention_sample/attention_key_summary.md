# Attention 学习总结（关键内容）

本文整理本轮关于 Attention 的关键认知，目标是回答两个问题：
- **Attention 矩阵到底是什么？**
- **模型在生成时为什么会给不同 token 不同权重？**

---

## 1. 本轮核心疑问清单

围绕 `What's the weather like in Vancouver right now?`，主要有这些疑问：

1. Attention 矩阵怎么理解？
2. 为什么一个 token 要看其他 token？
3. 模型是不是先完整理解再输出？
4. 生成时输出 token 和输入 token 的关系是什么？
5. Transformer 怎么“知道”哪个 token 权重大、哪个小？

---

## 2. 一句话直觉

> 一个词单看往往不够，模型需要结合上下文来决定这个词“到底是什么意思、该如何继续生成”。

所以 Attention 本质是：
- 当前 token 在计算时
- 对上下文各 token 的“参考分配”
- 看得多 = 权重大，看得少 = 权重小

---

## 3. 用句子示例理解 Attention 矩阵

示例句子：

`What's the weather like in Vancouver right now?`

简化 token：
- `What's` / `the` / `weather` / `like` / `in` / `Vancouver` / `right` / `now` / `?`

下面是**示意**（不是真实跑出来的精确数值）：

| 输出步（行） | What's | the | weather | like | in | Vancouver | right | now | ? | 解释 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---|
| 生成 `The` | 0.05 | 0.03 | **0.28** | 0.06 | 0.05 | **0.24** | 0.12 | **0.14** | 0.03 | 开头先抓任务词+地点词+时间词 |
| 生成 `weather` | 0.04 | 0.04 | **0.36** | 0.08 | 0.05 | **0.18** | 0.10 | 0.11 | 0.04 | 进一步确认“天气任务” |
| 生成 `in` | 0.03 | 0.03 | 0.18 | 0.08 | **0.12** | **0.36** | 0.08 | 0.09 | 0.03 | 准备连接地点，`Vancouver` 权重升高 |

如何读这张表：
- **行**：当前正在生成哪个输出 token
- **列**：当前这一步“参考了哪些输入 token”
- **数值**：参考强度（通常每行加和约为 1）

---

## 4. “先理解再输出”还是“边理解边输出”？

正确说法是：

1. 先对输入做一次编码（初步理解）
2. 生成第 1 个 token
3. 再用“输入 + 已生成 token”继续算第 2 个 token
4. 循环直到结束

所以不是“彻底理解完再机械输出”，而是：
> **每一步输出都在动态重新利用输入信息。**

这就是为什么会看到“输出 token 与输入 token 的 attention 关系”。

---

## 5. 权重是怎么计算出来的（核心机制）

每一步生成时，模型会计算：

1. 当前步的 Query（`q`）
2. 上下文中每个 token 的 Key（`k_i`）
3. 相似度分数：`score_i = q · k_i`
4. 经过 softmax 变成权重：`alpha_i = softmax(score_i)`

`alpha_i` 就是 attention 权重：
- 分数高 -> 权重大
- 分数低 -> 权重小

这些并不是人工规则，而是通过训练（反向传播）学到的参数结果。

---

## 6. 为什么会有“多头”？

单一关注模式不够，多头可理解为“多个观察角度并行”：
- 某些头偏语法关系
- 某些头偏实体对齐（地点、人名）
- 某些头偏长距离依赖

最后综合多个头的信息，生成更稳。

---

## 7. 最终认知（可直接记住）

1. Attention 矩阵是“谁在看谁、看了多少”的分配表。
2. 生成不是一次性理解后输出，而是每一步都在动态参考输入。
3. 权重来自 `q·k + softmax` 计算，参数由训练学得，不是手工硬编码。
4. 看 Attention 图时先问三件事：
   - 这一步在生成什么词？
   - 它最关注了哪些输入词？
   - 这些关注是否符合语义任务（任务词/地点词/时间词）？
