# Git 推送 403 权限拒绝的解决方法

当执行 `git push` 时出现 “Permission denied” 或 403 错误，通常是因为当前使用的凭据没有该仓库的推送权限。本文说明如何通过生成 GitHub Classic Token 并更新本地凭据来解决。

## 1. 现象说明

推送时终端可能看到类似输出：

```
git.exe push --progress "origin" main:main
Logon failed, use ctrl+c to cancel basic credential prompt.
remote: Permission to richest-qi/ai-agent-book-projects.git denied to richest-qi.
fatal: unable to access 'https://github.com/richest-qi/ai-agent-book-projects.git/': The requested URL returned error: 403
```

表示当前账号（如 `richest-qi`）对该仓库没有推送权限，或使用的密码/凭据已失效（例如未使用 Personal Access Token）。

---

## 2. 解决步骤

### 2.1 生成 Classic Token

1. 打开 **GitHub** → **Settings** → **Developer settings** → **Personal access tokens** → **Tokens (classic)**。
2. 点击 **Generate new token (classic)**。
3. 勾选 **repo**（即授予所有仓库的 Read & Write 权限）。
4. 生成后**复制并妥善保存**该 token（只显示一次）。

### 2.2 在 Windows 上清理并重置凭据

在命令行中执行：

```bash
git config --global --unset credential.helper
git config --global credential.helper manager
```

这样下次 `git push` 时会重新弹出凭据窗口，可输入新的 token。

---

## 3. 再次推送

执行：

```bash
git push origin main
```

在弹出的凭据窗口中：

- **username**：填 GitHub 用户名（例如 `richest-qi`）。
- **password**：填**刚生成的 Classic Token**（不要填登录密码）。

完成后即可正常推送。
